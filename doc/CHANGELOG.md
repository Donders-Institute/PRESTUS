# Changelog

Notable changes to this project are documented here. 

---

## v0.7-pre (development)

Adds defacing, an acoustic FOV crop, multi-transducer incoherent summation, GUI updates for Placement, Multi-Transducer, and Calibration tabs, and a standalone PyQt6-based Python GUI. Introduces BabelBrain and jwave as selectable acoustic solver backends; BabelBrain also contains a CT path for HU-based skull property mapping, and a thermal wrapper. Principal-axis grid alignment becomes the new default for multi-transducer setups. Three additional pCT skull-property algorithms are added (Webb, Pichardo, McDannold). The transducer calibration library moves to `config/calibration/` and gains a version manifest, geometric-baseline entry generation, and geometry-only calibration mode. HPC post-run reporting is automated via a lightweight dependent SLURM job. Several fixes address MI computation, thermal crashes, multi-frequency transducer handling, and path-rename regressions across NeuroNav and calibration workflows. Async multi-transducer simulations are stabilised with a shared grid preproc stage, ras_plus enforcement, and a fix for a coordinate-space bug that could corrupt per-transducer positions when resuming against a cached grid. Pulse amplitude ramping is modelled in thermal simulation. TUS_entry is added as a new transducer placement mode. The multi-target NeuroNav extraction toolkit gains a documented, tiered target-resolution module (`neuronav_resolve_target`) supporting study-supplied pre-hoc target lookups and multi-convention `EntryTarget` label matching.

#### Matrix arrays: steering correction, flat arrays, element rotation

- **New:** steering correction of matrix arrays. Hydrophone focal peaks at a set of steering targets are fitted as measured / modelled (one constant, or a quadratic surface over the steering range when leave-one-out cross-validation shows it helps; `fit_steering_correction`), stored in the transducer library (`build_steering_correction`) and applied by scaling the element drive by k(target) (`create_matrix_karray`, `transducer.matrix.steering_k`). The modelled peak comes from a new free-field Rayleigh model of matrix arrays (`matrix_rayleigh_pressure`, `matrix_focal_peak`). New keys `transducer.matrix.use_steering_correction` (default `true`; only acts when the library or the config holds a correction) and `transducer.matrix.steering_correction`. Matrix transducers without a library entry are simulated as before.
- ⚠️ **Fix:** flat matrix arrays (`is_curved: false`) failed: elements were aimed at a focus at infinity (NaN orientation) and file coordinates were shifted by an infinite radius. Flat elements now face +z, file coordinates of a flat array are read in the transducer frame, and a flat array with `bowl` elements errors.
- **New:** `matrix_shape.extract_from_file.rot_col` gives each element's rotation about its normal, for arrays with rectangular elements in more than one orientation.
- **Fix:** `extract_from_file.file_path` given as an absolute path to a file outside the MATLAB path was rejected (`which` finds only files on the path); an existing path is now used as given.
- **Docs:** *Steering correction of matrix arrays* (transducer library), Parameters.
- **Tests:** `test_steering_correction`.

#### pCT: CT calibration for the k-plan density mapping

- **New:** `pct.density_calibration` selects the HU→density table of `mapping_density: k-plan` (`medium_pct_density_calibration`). HU depend on scanner, kVp and kernel, so a UTE→HU line should be paired with the table of the CT it was fitted to. `''` (default) keeps k-Plan's default table, so existing configs give identical results. Shipped in `config/ct_calibration/`: `kplan_default`, `ucl_lowdose_80kvp` (the 80 kVp CT behind `treeby`; from ucl-bug/petra-to-ct via petra2density) and `cph2025` (petra2density's calibration); any CSV path also works (e.g. a phantom scan of your own scanner, or a table for a study-specific `custom` line). The resolved table is printed by `medium_setup` and stored in the medium statistics. The setting is ignored with a warning for other density mappings.
- **Coupled use:** the skull mapping and the density calibration are one choice: a UTE→HU line returns HU on the scale of the CT it was fitted to. `skull_mapping: treeby` (fitted to 80 kVp CT) belongs with `mapping_density: k-plan` and `density_calibration: ucl_lowdose_80kvp`; PRESTUS warns otherwise. The same pairing makes lines fitted at any other kVp or scanner usable (own line as `custom`, own phantom table as a CSV), without converting HU.
- **Docs:** *Mapping skull density* (CT calibration), *Pairing a UTE→HU mapping with its CT calibration* (new), Parameters.
- **Tests:** `test_pct_density_calibration`.

#### pCT: kosciessa fit takes each width crossing around its own peak

- ⚠️ **Fix:** `pct_skullmapping_fit` took the quarter-max crossings around the global maximum of each histogram, not around the peaks it identified. When charm's trabecular label holds many voxels with air-like UTE (a near-zero mode that is the histogram maximum), the "upper trabecular crossing" landed below the crossover (sub-109 of the pCT database: points 0.03 / 0.63 / 0.20 → −1426·u + 1376 instead of about −1600·u + 1880). The crossings are now taken around the cortical peak and the x-weighted trabecular peak, and a warning is issued when the three points are not in ascending order. Fits whose histogram maxima are the identified peaks are unchanged. **Rerun `kosciessa` pCTs that warn or whose `pCT_skull_mapping.png` shows a near-zero trabecular mode.**

#### Grid orientation: beams averaged as axes

- ⚠️ **Change:** `grid.mode: focal_axis` (the default) averages the beams as axes, not directions (new `mean_beam_axis`): a beam pointing against transducer(1)'s is reversed before averaging. Before, opposed (bilateral) beams cancelled, the mean fell below `grid.focal_axis_min_norm` and the grid silently fell back to transducer(1)'s axis, so transducer 2 was drawn at the full angle between the axes (41° in the two-transducer benchmark). Now each beam is tilted by about half of it (21°). Same-side converging beams and single-transducer runs are unchanged. **Multi-transducer runs with opposed transducers get a different grid**; rerun them rather than reusing caches.
- **Removed:** `grid.mode: principal_axis` (an alias of `focal_axis` since it was deprecated) now errors, and the unused `preproc_align_to_principal_axis` is deleted.
- **Docs corrected against the code:** `focal_axis` was described as equal to the inter-transducer axis for bilateral setups (it fell back to transducer(1)'s axis); the shared-grid async mode was described as aligned to the mean focal axis in all cases; per-transducer differences between grid modes were attributed to beam incidence through the skull (they are discretisation); `ras_plus` was described as the k-Plan / BabelBrain convention (PRESTUS hands BabelBrain a beam-aligned domain); several headers named `transducer_axis` as the default.
- **Tests:** `test_mean_beam_axis`.

#### Fix: partial-FOV runs on another run's grid, and async partial-FOV combines

- ⚠️ **Fix:** a run reusing another run's grid cache got the cached `grid` settings in full (`load_grid_cache_file`), including `grid.acoustic_fov_*`. A partial-FOV run on a full-grid run's cache simulated the full grid without saying so, and the async joint (thermal) job of a partial-FOV run cropped the back-projected combined field again and failed. The cache now supplies only what the grid stage computes (`dims`, `default_dims`, `resolution_mm`, `display_orientation`); every other grid setting is the run's own. Affected: partial-FOV runs with `io.preproc_affix` pointing at a full-grid run (they ran on the full grid), and async runs with a partial FOV (the joint job failed).
- ⚠️ **Fix:** `combine_async_intensity` saved file 1's partial-FOV `kgrid` and `acoustic_grid_dims` with the full-grid combined field. Both now describe the full grid.
- **Change:** grid and medium cache signatures no longer include `grid.acoustic_fov_*`, which is applied after these stages. A cache built with or without a partial FOV can be reused by a run with the other setting; older caches that recorded these keys are accepted.
- **Change:** an acoustic cache on another grid now stops a run that sets up no source (`acoustic_stage:staleCacheNoSource`), with the grid sizes and the likely cause, instead of failing inside `acoustic_wrapper`.
- **Tests:** `test_grid_cache_transducers`, `test_multitransducer_fov`, `test_cache_signature`.

#### Fix: a reused grid cache replaced the run's transducer settings

- ⚠️ **Fix:** a run reusing another run's grid cache (`io.preproc_affix`, `io.reuse_upstream_caches`) with the same number of transducers got the cached transducer array in full (`load_grid_cache_file`), so its own drive, phases and ISPPA targets were replaced by those of the run that built the grid. It now keeps its own transducer settings and takes only the grid-space `trans_pos` / `focus_pos` from the cache. Affected: runs on another run's grid whose transducer settings differ from it, e.g. a coherent run with targets on an async run's grid (it ran untargeted). Runs reusing a cache built with more transducers (async per-transducer jobs) were and are handled separately.
- **Tests:** `test_grid_cache_transducers`.

#### Fix: multi-transducer sources built every transducer from transducer 1

- ⚠️ **Fix:** `source_create` built transducers 2..N from transducer 1's settings (drive amplitude, phases, element geometry, frequency); only their positions were their own. The conversion loop read each transducer from an array it had just re-created from transducer 1 (since 2026-04-08, `fa71b416`). **Coherent multi-transducer runs are affected** whenever the transducers differ in any of these settings — e.g. two transducers with their own library phases, where the second was focused with the first one's phase profile. Single-transducer, async (one transducer per sub-run), sequential and BabelBrain runs are not affected. Re-run coherent multi-transducer acoustics.
- **Tests:** `test_source_multi_transducer`.

#### Coherent multi-transducer runs: one ISPPA target per transducer

- ⚠️ **Change:** in a coherent run with several transducers, `transducer(k).target_isppa_wcm2` now sets the free-water ISPPA of transducer k alone. Before the simulation, `coherent_drive_calibration` multiplies each transducer's `elem_p_amp` by √(target / baseline), with the baseline from that transducer's calibration ISPPA (target within 1 %) or a free-water simulation of it alone; the combined field is not rescaled afterwards. Before, only `transducer(1)`'s target was read and the combined field was scaled so that its free-water peak (both transducers firing) met it; the other targets were silently ignored. **Coherent multi-transducer runs with targets (including the default 30 W/cm²) give different fields**; caches from before carry no `acoustic_provenance.coherent_drive` and are refused when targets are set (`prestus:isppa:coherentWithoutDriveCalibration`).
- **Errors instead of a wrong scaling:** ISPPA sweeps (vector targets) with coherent multi-transducer runs (`prestus:isppa:coherentSweep`, each point needs its own simulation; async supports sweeps), and `path.acoustic_input` with several transducers and targets.
- **Docs:** *Multi-transducer — ISPPA targets* (new); `target_isppa_wcm2` described as the transducer's own target in *Parameters*, *ISPPA targeting* and `config_default.yaml`. The Nexus flags coherent sweeps before launch.
- **Tests:** `test_coherent_drive_calibration`.

#### BabelBrain backend: one transducer, beam along the grid z axis

- ⚠️ **Fix:** PRESTUS hands BabelBrain its simulation grid unrotated, and BabelBrain places the transducer on that grid's z axis through the focus. A beam off z (any multi-transducer run on a shared grid; `grid.mode: ras_plus`) was therefore simulated along z, silently, aimed at the right focus. New `babelbrain_check_geometry` errors instead: more than one transducer with `acoustic_backend` or `thermal_backend` `babelbrain` (at config load, at the start of `async_transducer_pipeline` and in `babelbrain_wrapper`), and a beam more than 2° off the grid z axis (in `babelbrain_wrapper`). The Nexus flags both before launch.
- **Removed:** multi-transducer support with BabelBrain (coherent recursion in `babelbrain_wrapper`; async). Use `kwave` or `jwave` with `thermal_backend: kwave` for multi-transducer runs. None of the v05 BabelBrain runs used several transducers or `ras_plus`.
- **Docs:** *BabelBrain — Geometry limits* (new); the limitations table had listed coherent and async multi-transducer as supported.
- **Tests:** `test_babelbrain_geometry`; Nexus `test_babelbrain_geometry_rules`.

#### Starting from earlier stage outputs: JSON sidecars

Within-run caches (`cache/`, `io.overwrite_files`) and complete stage outputs that a later, separate run starts from are now kept apart. Each stage output gets a JSON sidecar next to it (as in BIDS) with a common header (`sidecar_version`, `kind`, `created`, `generated_by`, `subject_id`) and a `signature` of the settings it depends on, compared on reuse under `io.cache_signature_check`. See [Starting from earlier stage outputs](doc_outputs.md#starting-from-earlier-stage-outputs).

- **New `placement.reuse`** (`auto` | `always` | `never`, default `auto`): a heuristic, PlanTUS or TUS_entry run recorded in its run folder is reused when its settings match, independent of `io.overwrite_files`; on a mismatch `auto` runs the placement again (under `overwrite_files: never` it errors as before). ⚠️ With the default `overwrite_files: always`, a matching recorded placement is now reused instead of recomputed. The record is `placement_run.json` (`write_placement_record` / `read_placement_record`); `placement_run.mat` records are still read
- **Pseudo-CT sidecar**: `pseudoCT.json` now records the skull mapping as a signature (plus segmentation folder and PRESTUS version). A reused pseudo-CT made with another `pct.skull_mapping` stops the run (`check_pct_sidecar`); older `pseudoCT.json` files (`SkullMapping` only) are checked too, a pseudo-CT without one is used with a warning
- **Pressure-map sidecar and `path.acoustic_input`**: every run writes `…_T1w<affix>_pressure.json` next to its pressure NIfTI (free-water ISPPA level of the map, baseline, transducer, backend, signature). `path.acoustic_input` (replaces `io.external_acoustic_nifti`, which is migrated with a deprecation warning) starts a run from such a map: it is checked against the current settings, put onto the run's grid (incl. an acoustic FOV), rescaled to `transducer.target_isppa_wcm2`, and acoustic analysis now runs on it (it was switched off before). The free-water baseline is skipped. Thermal-only grid settings (`grid.thermal_*`) do not count as a mismatch
- **Docs corrected against the code** (*Modules*): the partial-run recipes assumed grid, medium and acoustic caches that are only written with `io.save_*` on, and switching off a stage whose cache is missing does not error but continues without that stage's results
- **Tests**: `test_stage_sidecars` (unit level); `test_placement_paths` covers the `placement.reuse` modes and the JSON record

- **New `path.placement`** (default `<path.sim>/placement`): heuristic, PlanTUS and TUS_entry runs write everything they produce to `<path.placement>/sub-XXX/<mode>/<target_name>/` (`placement_run_dir`). A placement does not depend on the acoustic setup, so several setups can share one folder. See [Where outputs live](doc_outputs.md#where-outputs-live), which also sets out the levels inputs → subject derivatives → placement → simulation

#### Calibration: within-ring velocity profile

- **Ring profile** (`fit_ring_profile`): an optional model of how each ring vibrates across its width — every ring split into sub-rings with complex weights shared by all focal depths, fitted jointly on the measured axial profiles (smoothness penalty, near field from 4 mm), while each depth keeps one phase and gain per channel. It reproduces CTX near-field / focal peak ratios that uniform rings cannot (CTX-500-026, against an unregularised uniform-ring fit: median R² on held-out depths 0.957 → 0.989, ratio error 7× → 33 %). Off by default; selected with *Ring profile* in `calibration_gui` and the Nexus Calibration page, `RingProfile` in `refine_transducer_library` / `calibrate_library_entry` / `calibration_fit`, `ring_profile` in `config_calibration.yaml`, `RING_PROFILE` in `build_transducer_library`. Stored in `global_model.ring_profile`; `library_transducer` resolves the sub-ring geometry for every library function, the loader drives each sub-ring with its weight (`ring_profile_drive`), and sub-rings steer with their ring (`annular.steer_r_mid_mm` in `compute_phases` / `steering_path_lengths`). `plot_ring_profile` shows the fitted profile. Off-axis hydrophone data (`OffAxis`, e.g. radial profiles of transverse planes) are fitted with the axial profiles through the new `field_transfer_matrix` (Rayleigh integral off the axis); on CTX-500-026 hydrophone planes, the shipped library fit already predicts the transverse planes well (focal plane R² 0.97) but not the axis and near field (0.87; XZ near field 0.26); a profile fitted to axial profiles plus one transverse plane improves those (0.97; 0.65) and keeps the focal plane (0.98), while a profile fitted to axial profiles alone loses the transverse planes. Benchmark: `code/diagnostics/calib_ring_profile` (project repository)

#### Free-water grid sizing and k-Wave drive metrics

- **`grid.default_dims: 'auto'`** for water simulations (`water_grid_dims`): aperture + 2 × `grid.water_margin_mm` (default 5 mm) laterally, focal distance from the bowl + `grid.z_beyond_focus_mm` (default 40 mm) axially, as the acoustic FOV of head simulations; `[Nlateral, Naxial]` on axisymmetric grids. For the shipped transducers this is 15–80 % of the points of the 144×144×400 grid
- ⚠️ **Change: `grid.default_dims: 'auto'` is the default** (was `[144, 144, 400]`). The k-Wave drive benchmark (three transducers × three depths, 2026-10) found the same free-water ISPPA (ratio 1.0000 ± 0.00003) and focus (0 mm) as the 144×144×400 grid, on 3D and axisymmetric grids. Free-water results of annular transducers change only by this discretisation-level amount; run times drop. A non-annular (matrix) transducer placed by `trans_pos`/`focus_pos`, which are grid indices, keeps `[144, 144, 400]` (`[144, 400]` axisymmetric) with a warning. The MATLAB GUI shows `'auto'` as 0 0 0 (and writes 0 0 0 back as `'auto'`); before, it would have written the widget values over a string. `kwave_grid_dims: []` in `config_calibration.yaml` now resolves to `'auto'`
- **`kwave_calibrate_drive`**: `GridDims` option (`kwave_grid_dims` in `config_calibration.yaml`), and absolute agreement in its report (`kwave_drive_metrics`): ISPPA error of the analytical drive (`isppa_err_pct`), intensity at the measured focus, k-Wave / Rayleigh ISPPA at the same drive, and RMS error of the absolute profile before and after the drive correction; plus run time and grid size per simulation. The peak-normalised R² it reported before could not show a wrong level

#### Calibration: static joint model removed

- ⚠️ **Removed:** the static joint calibration model (one depth-independent per-ring offset and gain fitted over all depths): `LIBRARY_MODE = 'static'` (with `FIT_OPTIONS`, `GATE_WORST`) in `build_transducer_library`, `Mode = 'static'` in `calibrate_library_entry`, `refine_transducer_library` and `calibration_fit`, `calibration.phase_mode: multi_depth` in `calibration_transducer`, and *Static model (joint, debug)* and the *c steer* option in `calibration_gui` and the Nexus Calibration page. It was kept for debugging only; no benchmark showed it ahead of per-depth refinement, and every shipped entry is per-depth. These options now raise an error. #### Backend accuracy (ITRUSST intercomparison)

- ⚠️ **Axisymmetric annular arrays**: `source_create` placed each ring (inner diameter > 0) as an arc with its midpoint at the apex plane instead of on the bowl, and aimed it at the (steered) focus instead of the bowl's centre of curvature. The outer rings of CTX and IGT transducers sat 1–2 wavelengths too far forward, so the rings added up with wrong relative phases. The k-Wave drive benchmark (2D axisymmetric vs 3D, free water) showed focal ISPPA at 7–117 % of the 3D value, the focus moved by −67 to +35 mm, and a negative profile R². Rings are now the segment of the bowl's arc between their inner and outer radius (midpoint on the bowl surface, diameter = chord), all aimed at the centre of curvature. A single element (ITRUSST BM1, the previous physics tests) was not affected; 3D runs were not affected. **Rerun axisymmetric results of multi-ring transducers.** New physics test `test_axisym_annular_rings_match_oneil` (four rings in phase against O'Neil summed over the rings). Rerun of the drive benchmark: 2D / 3D focal ISPPA 0.98–1.03 with the same focus (CTX-250, CTX-500, IGT 10-ring; three depths each), so `kwave_calibrate_drive` with `axisymmetric2D: 1` is usable (about 1 min per depth, within ~3 % of the 3D drive); `doc_transducer_library.md` no longer marks it unreliable
- ⚠️ **jwave Helmholtz through skull**: jwave's built-in Helmholtz operator (∇²p − ∇ρ·∇p/ρ, spectral gradient of ρ) loses energy at density jumps: −26 % transmission through the ITRUSST BM3 cortical plate at 0.5 mm in 1D tests against the analytic solution, and 23–29 % low focal pressure on ITRUSST BM3–7 in 3D. `run_jwave_sim.py` now solves the conservative form ρ∇·((1/ρ)∇p) + k²p (1/ρ on the staggered points) with the source scaled by the local sound speed (new `jwave.helmholtz_operator: conservative`, default; `jwave` restores the previous operator). 1D tests: −0.2 % (BM3 plate), −3 % (BM4 layers) at 0.5 mm. jwave results through skull change (higher transmitted pressure); free-water results are unchanged except for the source scaling when the medium is slower than water somewhere
- **jwave with kWaveArray sources**: `grid.use_kWaveArray: 1` is no longer overridden to 0 for jwave. The kWaveArray CW source is written in factored form (`CWSourceMatrix.factors`). With the stair-stepped `makeBowl` source jwave was ~9 % low in free water (ITRUSST BM1, 0.5 mm). Flat (piston) elements now also run with jwave
- **k-Wave with `fit_alpha_power: 0`**: `medium_setup` passed a per-voxel `alpha_power` array, which k-Wave rejects (`medium.alpha_power must be scalar`). It now passes the single power law, and errors with a clear message when tissues have different powers
- **Axisymmetric → 3D conversion**: `convert_axisymmetric_to_3d` failed on integer label maps (`interp1` takes double/single only), after the simulation had finished. Labels are now expanded as double and returned in their class
- **BabelBrain label path**: an empty `babelbrain.ct_mapping` read from YAML as the string `""` counted as set (`isempty("")` is false), so label-based runs stopped with `ct_mapping is set but no pseudoCT was supplied`. `babelbrain_wrapper` now converts it to char

- **Solver bridge** — `babelbrain_wrapper` translates the PRESTUS grid, medium masks, and transducer geometry into BabelBrain's NIfTI input format, invokes the Python FDTD engine, and returns `sensor_data` in the same format as the k-Wave backend
- **Transducer preset resolution** — transducer serial is automatically matched to a named BabelBrain preset; novel transducers are written to a temporary CSV so BabelBrain can handle them without a matching built-in entry
- **Calibrated phase export** — optimised element phases from the transducer library are exported as an `OptimizedWeightsFile` (H5); geometric (Rayleigh) focusing is used as a fallback when no library entry is present
- **Debug source dump** — with `simulation.debug: 1`, `run_babelbrain_case.py` writes `<target>_babelbrain_source_dump.h5` (sub-element positions, surface-area weights `ds`, per-ring geometric steer `AllPhi`, applied weights, and preset `FocalLength`/`InDiameters`/`OutDiameters`) the first time `AdjustWeightAmplitudes` runs. Lets the source BabelBrain actually builds be compared offline against the ideal analytical geometry (`code/analyze_babelbrain_source_dump.py`) — used to isolate a residual water-focus discrepancy that is solver-independent (identical for Rayleigh and FDTD) and does not converge with PPW, i.e. a source-geometry difference rather than propagation or resolution
- **Water-field solver made configurable (`babelbrain.use_rayleigh_for_water`, default `false`).** `bUseRayleighForWater` was hardcoded `True`, so BabelBrain computed the water-only field with the analytic Rayleigh–Sommerfeld integral while every other PRESTUS backend (k-Wave, jwave ×3) solves the full wave equation on a grid. That solver-class mismatch made BabelBrain a systematic outlier in water: a **rigid ~1.5 mm axial offset of the whole profile** (near-field lobes and focus alike — a propagation-model difference, not a coordinate bug) plus a **~12% higher peak** (Rayleigh has no grid dispersion, so it focuses slightly tighter). Now exposed as a config flag and threaded through `babelbrain_wrapper` → `run_babelbrain_case.py` (`--no_rayleigh_for_water`) → `RunCases(bUseRayleighForWater=...)`, and reflected in the standalone `export_babelbrain_inputs` template. Default is `false` (full-wave FDTD water) so BabelBrain is comparable to the other backends on a like-for-like basis — the toolbox's purpose. Set `true` for BabelBrain's faster native behaviour / the exact linear free-field. Only affects water-only runs; the transcranial field always uses FDTD
- **BabelBrain thermal readback was misregistered.** Three bugs in the BabelBrain-thermal → PRESTUS path, found with beam-plane difference maps against k-Wave: (1) `read_babelbrain_thermal` reversed `z_vec` as for the acoustic `DataForSim.h5`, but the thermal arrays are already in `z_vec` order (BabelBrain flips on load and saves unflipped), so heating was mirrored about the focal marker — skull and pre-focal heating landed distal of the target (the `/TargetLocation` anchor did not reveal it where the marker sits mid-domain); (2) `babelbrain_thermal_wrapper` anchored on the acoustic-grid `sensor_data.focus_pos`, i.e. acoustic-FOV crop coordinates on the restored full thermal grid (sub-602 pFOV: heating placed on the far side of the head; 3.6% overlap with the beam) and the acoustic step on a separate thermal grid — it now uses the thermal grid's positions and step (`thermal_grid_setup` stores the unrounded `grid.thermal_focus_pos_exact` / `thermal_trans_pos_exact` / `thermal_resolution_mm`); (3) temperatures outside BabelBrain's thermal domain were zero-filled (0 °C → a −37 °C `heatrise` in the NIfTIs); they are now resampled as rises over `BaselineTemperature`; (4) the thermal output keeps `_DataForSim` in its name (`…_DataForSim-ThermalField_AllCombinations.h5`), so the exact-name lookup missed it and fell back to the newest `*ThermalField*.h5`. BabelBrain thermal results from before this fix should be re-run.
- **BabelBrain Tx placement uses the actual apex-to-target distance.** The mechanical placement correction was `preset FocalLength − focal_distance_bowl`, i.e. it assumed the target always sits at the nominal focal depth. With planned/pFOV placements it does not (sub-602 pFOV: `|focus_pos − trans_pos|` = 71.25 mm vs `focal_distance_bowl` = 92.3 mm), so BabelBrain's transducer sat ~21 mm further from the head than in k-Wave/jwave. The whole field was shifted proximally relative to the anatomy (BabelBrain's own water-only focus at 48 mm EP vs k-Wave 69 mm), the beam met the skull closer to focus, and transcranial Isppa came out ~1.7× too high (12.8 vs 7.6 W/cm²; skull Isppa 7.2 vs 2.1). The correction is now `preset FocalLength − |focus_pos − trans_pos|·res_mm` (new shared helper `babelbrain_placement_correction`, used by `babelbrain_wrapper` and `export_babelbrain_inputs`); `focal_distance_bowl` remains only as a fallback without `trans_pos`. Also: the free-water baseline (`--water_only`) run now receives `--source_amp_pa` (it ran at BabelBrain's ~50 kPa default, giving a ~10× too-low `freefield_isppa_wcm2`); and `export_babelbrain_inputs` resolves `computing_backend: auto` (and names such as `cuda`) to BabelBrain's integer via the new `resolve_bb_backend` (the exported `RunBabelBrain.py` contained `COMPUTING_BACKEND = 97, 117, 116, 111` — the char codes of `'auto'` — a Python SyntaxError) and writes the placement-corrected `TxMechanicalAdjustmentZ`. Follow-up: when the grid starts at the apex (pFOV crop at `trans_pos`) the bowl rim protruded into BabelBrain's domain and BabelBrain snapped the source back 5.5 mm; `write_babelbrain_input` now trims the transducer-side water slab up to the rim (+1 voxel) so the source lands exactly on `trans_pos`. The trim depth is `d_apex + bowl_depth` (the first version used `bowl_depth − d_apex`, correct only with the apex at the grid face: with the apex 7.5 mm inside the grid, as in the bone-slab phantom, nothing was trimmed and BabelBrain moved the source 13.5 mm back, shifting the focus ~14 mm proximally). The CT companion volume is now flipped only when the mask is (it was always flipped, mirroring it for beam −z).
- **Non-CT bone Q correction now defaults to 1.0 (was BabelBrain's CT-mode 3.0).** A flat bone-slab phantom showed realised bone attenuation scales ~1/Q: Q = 3 realised only 29% of the specified `alpha_coeff`, Q = 1 91% (k-Wave 91%), so BabelBrain transcranial Isppa was too high (sub-602 pFOV 10.6 vs 7.6 W/cm²). New `babelbrain.q_correction` (→ `run_babelbrain_case.py --q_correction`) overrides it on both paths.
- **Resample anchor bowl↔exit-plane offset fix.** `read_babelbrain_output`/`resample_babelbrain_vol` paste BabelBrain's field onto the PRESTUS grid by anchoring the plane `z = focal_length_mm` onto `focus_pos`. `babelbrain_wrapper` set `focal_length_mm = preset FocalLength` (the geometric focus / centre of curvature = BabelBrain's label-5 marker), but `focus_pos` is the *intended* focus (`focal_distance_ep` from the exit plane). Since BabelBrain's marker sits at `z = FocalLength` and its exit plane at `z = FocalLength − dist_geom_ep = bowl_off`, the intended focus is at `z = bowl_off + focal_distance_ep = focal_distance_bowl` — so anchoring on `preset FocalLength` conflated the two and shifted the entire pasted field proximal by `dist_geom_ep − focal_distance_ep` (the bowl↔exit-plane offset), putting the water focus at ~63–67 mm instead of ~69 mm. Verified against the native `DataForSim.h5`: BabelBrain's peak depth-from-exit-plane in its own z axis (`z_peak − bowl_off`) is ~70.6 mm, matching k-Wave (69.2) — the anchor was the sole discrepancy. Fixed in two places: (1) `babelbrain_wrapper` now passes `focal_length_mm = focal_distance_ep + bowl_off` (= `focal_distance_bowl`); (2) `read_babelbrain_output`/`read_babelbrain_thermal` no longer **override** that anchor with BabelBrain's `/TargetLocation`. That "ground-truth" override was the real blocker — `/TargetLocation` is the label-5 marker at the preset `FocalLength` (the geometric focus / centre of curvature), which differs from the intended focus by `dist_geom_ep − focal_distance_ep` under electronic steering; forcing it onto `focus_pos` reintroduced the full proximal shift and silently reverted fix (1). `/TargetLocation` is now used only as a fallback when no anchor is passed. Thermal resampling inherits the corrected anchor via `sensor_data.focal_length_mm`
- **`AllPhi`-referenced weight correction (exact drive reproduction).** BabelBrain realises PRESTUS's annular drive as `angle(u0) = AllPhi + angle(weight)`, where `AllPhi` is BabelBrain's internal phase-conjugation steer and drives each element as `sin(ωt + angle(u0))` — the same convention as k-Wave's `createCWSignals`. The previous handoff computed the weight as `phases_rad − geo` with an *analytic* `geo` (`compute_phases`), which does not reproduce BabelBrain's voxelised-grid `AllPhi`; no analytic aim closed the gap (attempts left the water focus 2–13 mm off and, at some aims, amplitude too high). Fixed by referencing the correction to BabelBrain's OWN `AllPhi`: `export_babelbrain_weights` now also writes the raw intended drive (`/DRIVE/phases_rad`, `/DRIVE/amp_ratio`) into the weights H5, and `run_babelbrain_case.py`'s annular-weight patch rebuilds the per-ring weight as `amp_ratio · exp(i·(phases_rad − AllPhi))` using `BasePhasedArrayProgramming` (`exp(i·AllPhi)`, available before `AdjustWeightAmplitudes` runs), then expands to subelements. Result: `angle(u0) = phases_rad` exactly, so BabelBrain's source equals the intended (k-Wave-identical) drive independent of any analytic reconstruction. `convert_weights_if_needed` carries `/DRIVE` through the BabelBrain-format conversion. The analytic `/CALIBRATION` delta remains as a fallback for consumers that don't apply the correction; with the correction active the delta's aim reference no longer affects the result. The earlier `exp(-i·delta)` → `exp(+i·delta)` sign correction is subsumed by this (the `+i` convention is what makes `angle(u0) = phases_rad`)
- **Optional whole-profile phase calibration** (`babelbrain.profile_calibration`, default **off**) — `calibrate_babelbrain_phase_profile` re-fits the BabelBrain drive phases whole-curve: **target** = continuous-bowl O'Neil profile (`focusedAnnulusONeil`), **forward model** = discrete-ring Rayleigh (`rayleigh_axial_intensity`, BabelBrain's water physics), reusing the existing `perform_global_search` → `phase_optimization_annulus_full_curve` optimiser (uniform whole-curve weighting, L2 regularisation toward the library phases). Non-circular (O'Neil target ≠ Rayleigh forward), needs no external data, BabelBrain-specific (only the weights delta consumes it). Off by default because, with the aim-reference fix above, BabelBrain already reproduces the library phases and matches the k-Wave/jwave cluster; this refinement targets the continuous-bowl ideal, which sits slightly distal of that cluster. Falls back to the library phases on any fit failure

- **Thermal timing mapping actually corrected** — a previous pass at this claimed `ptd`→DurationUS/`ptri−ptd`→DurationOff/`ptrd/ptri`→Repetitions, but the code still had `duration_s = t.ptrd` (the *total* span across all repetitions, not one repetition's ON time) and `duration_off_s = t.ptri - t.ptrd` (dead code, since `ptrd ≥ ptri` always makes this ≤0), and `Repetitions` was never actually passed to `run_babelbrain_thermal.py` (which defaulted `--repetitions` to 1). - **BabelViscoInput.nii.gz resampled to BabelBrain's own native resolution** — `write_babelbrain_input.m` previously wrote the mask at `parameters.grid.resolution_mm` (e.g. 0.75 mm). Its own step (`SpatialStep = Wavelength/basePPW`, e.g. 0.525 mm at 300 kHz/PPW 7) is generally finer than `resolution_mm`, so the same voxel count was silently interpreted as covering a smaller physical distance — compressing the whole simulated domain, and the transducer geometry drawn within it, by the ratio of the two resolutions (confirmed: proximal+distal zero-fill in the PRESTUS-resampled comparison summed to ~33 mm, matching `Nz*(resolution_mm - bb_native_res_mm)` almost exactly; peak pressure at target was correspondingly inflated ~2× beyond k-Wave/jwave). `write_babelbrain_input.m` now computes BabelBrain's own native resolution (mirroring `GetSmallestSOS`/`DensityToSSoSPichardo`) and resamples the label map (nearest-neighbor) and focal marker position to it before writing, so voxel spacing — and therefore physical domain size — matches what BabelBrain will assume

(The *acoustic* engine's numeric `COMPUTING_BACKEND` has no such MLX branch and its "4=CPU" mapping is unaffected.)
- **CT/pseudoCT path was non-functional — three independent guaranteed failures on any run with `ct_mapping` set.** (1) `CT.nii.gz` was written as a raw Hounsfield-equivalent float volume, but BabelBrain's CT path (`BabelDatasetPreps.py`/`BabelIntegrationBASE.py`) expects it to already be a quantized index map into a sorted unique-HU table, with that table saved separately as a companion `<prefix>CT-cal.npz` (key `UniqueHU`) that PRESTUS never wrote — `BabelIntegrationBASE.py` would raise `FileNotFoundError` trying to load it, and even without that, feeding raw HU floats where small integer table indices are expected is either an out-of-bounds crash or silently wrong bone material properties. (2) `CT.nii.gz` was written with no header/affine at all (default identity, 1mm voxels), while the tissue-label mask was correctly resampled/registered — the two files BabelBrain indexes by the same voxel coordinates would have mismatched shape and affine. (3) BabelBrain unconditionally expects an `AirRegions.nii.gz` companion whenever `bExtractAirRegions` (default `True`) is left enabled, which PRESTUS also never wrote — a second guaranteed `FileNotFoundError`. Fixed: `write_babelbrain_input.m` now optionally writes `CT.nii.gz` using the identical resampling/header/flip as the tissue mask (guaranteeing matching grids), `run_babelbrain_case.py` disables `bExtractAirRegions` (no air-region data is generated), and a new `_quantize_ct_for_babelbrain` step (run before `RunCases()`) quantizes the raw-HU CT to BabelBrain's own scheme (uniform 10-bit round-to-level quantization within the cortical/trabecular bone region) and writes the matching `CT-cal.npz`
- **Transducer preset `GEOM_TABLE` had fabricated/wrong reference geometry for every entry except R15473** — verified against the actual `default.yaml` for each preset: `CTX_500`/`CTX_250` were listed as 7-ring when their `default.yaml` defines 4 rings; `R15287` was listed as 4-ring/500kHz when it's actually 10-ring/300kHz (curvature 75mm, not 62.94mm); `R15646`, `H317`, `H246`, and `H301` were given entirely fabricated ring counts/curvatures/OD/frequency even though none of them are ring-array transducers at all in `default.yaml` — `R15646`/`H317`/`H301` are single-element focused transducers with mechanical/electronic XYZ steering (no `InDiameters`/`OutDiameters`), and `H246` has no geometry section at all. A real ring-array transducer with unrelated geometry could coincidentally satisfy one of these fabricated rows (±2mm radius/±3mm OD/±5% freq tolerances) and get silently routed to the wrong physical preset. `GEOM_TABLE` now only lists the four presets that are genuinely ring arrays (`CTX_500`, `CTX_250`, `R15287`, `R15473`), with values read directly from each `default.yaml`; the non-ring-array presets are only reachable via exact `SERIAL_MAP` lookup
- **Per-ring amplitude shading (`elem_amp`) was silently discarded in the BabelBrain weights export** — `export_babelbrain_weights.m` always wrote unit-magnitude (phase-only) weights regardless of `tr.annular.elem_amp`; BabelBrain's default per-ring drive uses a single uniform `SourceAmpPa` across all rings, and the *only* channel for non-uniform per-ring amplitude is the weights file's own magnitude. Any config with real apodization (non-identical `elem_amp` across rings — respected correctly by k-Wave/jwave) would silently simulate as uniform-amplitude in BabelBrain. `export_babelbrain_weights.m` now accepts an optional `elem_amp` and encodes each ring's amplitude ratio relative to the reference ring (`elem_amp(1)`, matching the ring already used for `--source_amp_pa`) into the weights magnitude; uniform (or omitted) `elem_amp` still produces the previous unit-magnitude behaviour. (The per-ring→per-subelement weight expansion in `run_babelbrain_case.py`'s `_patch_annular_array_weights` already replicates the full complex value including magnitude, so this needed no further changes there.)
- **MaterialMap debug resample switched from point-sampled nearest to majority-vote (`mode`)** — the debug `MaterialMap` NIfTI is resampled from BabelBrain's native grid (finer) onto the coarser PRESTUS grid; point-sampled nearest-neighbour there is a single-sample lookup per output cell, which can silently drop thin structures (sub-voxel cortical bone) that miss the sample point despite occupying real volume in the coarse cell. `resample_babelbrain_vol` now supports a `'mode'` method that forward-scatters each BabelBrain-native voxel into the PRESTUS cell it lands in and takes the most common label per cell, preserving thin layers; `read_babelbrain_output` uses it for `MaterialMap`. (Affects only the diagnostic overlay — the simulated medium itself comes from `write_babelbrain_input.m`, which UPsamples the PRESTUS mask to BabelBrain's finer native grid via nearest-neighbour, where no structure is lost.)
- **Auto-resolved PPW targeted the wrong reference sound speed** — `babelbrain_wrapper.m`, `write_babelbrain_input.m`'s standalone fallback, and `export_babelbrain_inputs.m` all computed `ppw_auto = round(c_min/(freq*resolution_mm))` using `c_min = medium_properties.brain.sound_speed` (~1562 m/s). BabelBrain's own resolution is actually governed by its Pichardo shear-speed floor (1102.515 m/s under the fluid-bone model), so this systematically under-shot the PPW needed to make BabelBrain's native resolution land close to `grid.resolution_mm` — e.g. for one benchmark, the wrong formula picked PPW=7 (native resolution 0.525 mm, a 43% mismatch needing substantial resampling) where the correct reference would pick PPW=5 (0.735 mm, ~2% off). All three now use the same Pichardo-floor-based reference as `write_babelbrain_input.m`'s `bb_native_res_mm`, minimizing (though, since PPW must be an integer against a fixed ratio, not always eliminating) the resampling still needed to reconcile the two resolutions
- **`babelbrain_wrapper` resolution-mismatch report used the wrong reference sound speed** — the pre-run "Resolution note"/"Grid mismatch" diagnostics estimated BabelBrain's native spatial step using plain water (`c_water=1500`), while `write_babelbrain_input.m`'s actual resampling (see above) uses `min(configured tissue speeds, 1102.515 m/s Pichardo shear floor)` — understating the true resample ratio by ~36% and suggesting a `grid.resolution_mm` value that would not actually eliminate resampling if followed. Diagnostic-only (simulation correctness was unaffected, since `read_babelbrain_output.m` derives its own resample-back scaling from the HDF5's actual coordinate vectors, not this estimate) — now uses the same formula as `write_babelbrain_input.m`
- **Free-water amplitude calibration re-based on intended-vs-achieved ISPPA instead of an analytic Rayleigh reference** — the `water_amp_calibration` step (Step 5b) previously scaled the returned pressure field by `k = p_rayleigh_peak / p_bb_water_peak`, comparing BabelBrain's free-water run to an in-repo Rayleigh–Sommerfeld diffraction model. This coupled the normalization to an analytic model (and, when the free-water baseline was mis-focused, produced a large factor that silently rescaled the reported dose). It now uses the same convention as `assemble_limited_fov_fields`: `k = sqrt(target_isppa_wcm2 / achieved_freewater_isppa)`, where `target_isppa_wcm2` is the transducer's configured intended free-water ISPPA and the achieved value is measured from the BabelBrain free-water run. It runs **only when a BabelBrain water baseline was actually simulated** (and a `target_isppa_wcm2` is set); otherwise the raw solver field is kept. Only `sensor_data` (acoustic analysis / freefield ISPPA) is scaled — the raw `DataForSim.h5` for the thermal backend is untouched, since BabelBrain's BHTE renormalizes to its own requested Isppa. A factor >4× (or <0.25×) now warns that BabelBrain's free-water run is under/over-achieving the intended ISPPA — a symptom of a mis-placed free-water focus rather than ordinary drive scaling
- **BabelBrain transducer placed on the wrong side of the axis for −z beams (mirrored/backwards field)** — `write_babelbrain_input` *unconditionally* pre-flipped the mask along dim 3 to cancel BabelBrain's own load-time `np.flip(axis=2)`, on the assumption that the aligned grid always runs the beam in +z (focus at a higher dim-3 index than the transducer). For head poses where `transducer_axis` alignment yields a **−z beam** (focus at a *lower* dim-3 index — verified on this benchmark: skin at dim3≈158, focus at dim3≈66), the unconditional flip put BabelBrain's acoustic source on the far (brain) side, firing backwards through the head: mirrored focal profile, focus tracking the distal boundary, and (in the axial-profile plot) a negative depth axis with the tissue order reversed. The flip is now conditional on the actual beam direction (`focus_pos(3) >= trans_pos(3)`), and the matching sign is applied to the output resample: `resample_babelbrain_vol` takes a `beam_sign` that mirrors only the depth (dim-3) mapping about the fixed focal anchor, threaded through `read_babelbrain_output`/`read_babelbrain_thermal` from `focus_pos` vs `trans_pos`. `trans_pos` is now passed into `write_babelbrain_input`, `read_babelbrain_output`, and (via `sensor_data.trans_pos`) `read_babelbrain_thermal`. +z-beam cases are unchanged (`do_flip=true`, `beam_sign=+1` — identical math), so only the previously-broken −z case is affected
- **BabelBrain narrow-beam domain no longer auto-enabled (truncated the returned axial field)** — the wrapper enabled BabelBrain's `bTightNarrowBeamDomain` whenever no PRESTUS-side FOV crop was configured (`tight_narrow_beam = isempty(fov_len_mm)`). BabelBrain's narrow-beam mode only FDTDs a tight region around/after the focus and handles the pre-focal path analytically (Rayleigh) *without emitting it into the output field*, so the returned axial profile was zero from the transducer up to ~the focus — e.g. a free-water benchmark returned zero everywhere except an ~40 mm band at the focus (focal peak location/amplitude correct, but the entire beam approach missing). It is now controlled by `babelbrain.tight_narrow_beam` (default **off** = full domain, so the pre-focal field is emitted); set it `true` only as a compute-saving measure for full-brain runs where the approach field is not needed. Force-disabled when a FOV crop is active (a second BabelBrain-side shrink would double-crop). A warning is emitted when running uncropped + non-narrow that BabelBrain sizes the domain from the full mask
- **BabelBrain PPW default raised 6 → 12** — `babelbrain_wrapper.m` defaulted `babelbrain.ppw` to 6 (native step ≈ 0.61 mm at 300 kHz), half the 12-PPW fidelity BabelViscoFDTD's own published benchmarks use. At 6 PPW the 2nd-order-time / 4th-order-space FDTD carries noticeably more numerical dispersion. The default is now 12 (native step ≈ 0.31 mm); the mask is upsampled to BabelBrain's native step regardless, and the result resampled back onto the PRESTUS grid, so this trades compute for accuracy without needing `grid.resolution_mm` to track it. Set `babelbrain.ppw` lower to prioritise speed
- **BabelBrain output was misaligned with the PRESTUS tissue mask by several millimetres — every downstream per-tissue consumer (not just plots) was silently wrong at the skull-brain interface.** BabelBrain's own `/MaterialMap` is byte-identical to the mask PRESTUS wrote (BabelBrain never alters tissue), so any position error in the output resample directly mis-registers the returned field relative to `medium_masks`/`segmentation` — and, unlike a single systematic offset, this one compounded two effects: (1) `CalculateRayleighFieldsForward` adds a skin-surface-dependent `ZDomainStart` (`GlobalStartSkin − LineOfSightStartSkin`, meant for BabelBrain's own GUI workflow with oblique full-head trajectories) on top of the wrapper's requested `TxMechanicalAdjustmentZ`, silently moving the source (observed: −5.5 mm on a pFOV benchmark, where lateral domain corners contain shallower skin than the on-axis skin); (2) the previous resample anchor compensated by pasting the field back at the *source's* realized position, which re-aligned the field to the transducer but dragged the (unchanged) tissue away from `medium_masks`. Net effect: `acoustic_analysis.m`'s `Isppa_brain`/`Isppa_skull` (partially mitigated by an earlier `bb_tissuemask_binary` patch, but not the axial-profile plot's tissue shading or the intensity-overlay colour scale/peak marker — see below), and, with no mitigation at all, every per-tissue **thermal** metric (`maxT_brain`/`maxT_skull`, `CEM43_brain`/`CEM43_skull`, etc. in `thermal_analysis.m`, which has no BabelBrain-aware branch) could misattribute the skull-brain reflection hotspot's heating to the wrong tissue. Fixed at the source in two parts so no downstream consumer needs BabelBrain-specific handling: (1) `run_babelbrain_case.py` monkey-patches `SimulationConditionsBASE.CalculateDomainZReference` to return `0.0` (`_patch_zdomain_reference`; disable with `--no_zdomain_fix`), so the source lands at exactly the requested position; (2) `read_babelbrain_output.m`/`read_babelbrain_thermal.m` now anchor the resample on **`/TargetLocation`** — the label-5 focal marker PRESTUS itself wrote at `focus_pos` — instead of the source position. This is the exact inverse of the forward mask transform, so tissue lands back on `medium_masks` by construction (verified on the same pFOV benchmark: overall label agreement 83% → 99%, bone 20% → 98%, skin 19% → 98%); with the source now correctly placed, the single marker-anchor aligns tissue *and* field simultaneously. The passed-in `focal_length_mm` (preset `FocalLength`) becomes a fallback used only when `/TargetLocation` is absent from the HDF5. A per-run sidecar (`<target>_prestus_anchor.json`) now reports the realized-minus-requested source position as a diagnostic (previously it recorded the anchor-correction delta, which no longer exists) — `read_babelbrain_output.m` warns when the residual exceeds 1.5 native voxels, which should only happen if `--no_zdomain_fix` was set or the ZDomainStart patch failed to apply. See [doc_babelbrain.md § Output alignment](doc_babelbrain_internals.md#output-alignment-tissue-marker-anchoring-and-the-zdomainstart-fix)
- **FOV-debug coverage plot/CSV reported the wrong side of the domain as truncated for −z beams.** `plot_babelbrain_fov_debug`'s `z_rel_focus_prestus` computation omitted the `beam_sign` correction that every other resample call in `read_babelbrain_output.m` applies, so for transducers where the beam runs −z along grid dimension 3 (focus at a lower index than the transducer — the same condition the earlier mirrored-field fix, above, handles), the debug figure's "zero-filled" shading and `zero_filled_proximal_mm`/`zero_filled_distal_mm` CSV columns were reported backwards (confirmed on a real run: reported `proximal=0mm, distal=25.9mm`, actual `proximal≈5.7mm, distal≈0mm`). Diagnostic-only — did not affect the simulated field or any numeric metric, only this debug plot's own coverage report. Fixed by applying `beam_sign` to the PRESTUS-side depth axis, matching `resample_babelbrain_vol.m`
- **Intensity overlay plots (`sub-*_intensity_{x,y,z}*.png`) coloured and marked by the unmasked global peak, which for BabelBrain lands in the skull-brain reflection hotspot rather than the brain focus.** `acoustic_analysis.m`'s `plot_overlay` call passed no colour-range option, so `plot_overlay.m` fell back to `clim_hi = max(overlay_image(:))` — the true global max, skull included — and separately used `highlighted_pos = masked_max_3d(acoustic_Ipa, ones(size(medium_masks)))` (also unmasked) for the peak marker. For BabelBrain runs this made the colour scale span up to ~4× the actual brain-focal value (compressing the whole brain field into the bottom of the scale) and put the blue peak marker on the skull-brain interface rather than the intended focus — reproducing the same class of mis-registration the `Isppa_brain` masking fix already addressed elsewhere, but in this specific plot path. (Independent of, and not fixed by, the resample-alignment fix above: even a perfectly-aligned skull-brain reflection hotspot is still physically the global intensity maximum for an elastic-skull solver — this plot never should have used the unmasked value.) `highlighted_pos` now uses the brain-masked peak when brain tissue exists (matching `Isppa_after_exit_plane`/`real_focal_distance`, already brain-masked); the intensity overlay's colour range is now capped at `Isppa_brain` (falling back to `Isppa` for non-layered media), matching the convention `plot_intensity_t1_overlay.m` already used for the separate T1w overlay

#### jwave acoustic backend

jwave (JAX-based) can be used as an acoustic solver via `acoustic_backend: jwave` (see [doc_jwave.md](doc_jwave.md)).

- Supports `time_domain` and `helmholtz` solvers (Helmholtz is the primary workflow), configurable PML size, and `single`/`double` floating-point precision
- Translates PRESTUS kgrid/medium/source structs to HDF5, invokes `run_jwave_sim.py`, and returns `sensor_data` in the same format as the k-Wave backend
- Axisymmetric grids and kWaveArray sources are not supported; both raise a clear error at pipeline entry
- `benchmark_jwave` test class compares k-Wave CPU, jwave time-domain, and jwave Helmholtz on a water phantom (wall-clock time, peak pressure, focal FWHM, field correlation)
- **Helmholtz convergence diagnostics** — spectral residual reported after each solve; optional time-domain FOV benchmark (`jwave.benchmark_fov_mm`) cross-validates GMRES convergence on a cropped subgrid; time_domain retained for cross-validation
- **Helmholtz lossless-water fix** — `alpha_coeff = 0` (truly lossless) made the Helmholtz operator near-singular, causing GMRES to stall and underestimate peak pressure by ~18% in free-water benchmarks. `run_helmholtz()` now applies an attenuation floor of 0.002 dB/(cm·MHz) before building the jwave Medium; this is the physical value for distilled water and has negligible acoustic effect (< 0.006 % over 100 mm at 500 kHz)
- **Grid crop margin** — `preproc_crop_grid` now reserves `pml_size` voxels when the jwave backend is active (jwave embeds its PML inside the declared grid N; k-Wave adds it outside)
- **Time-domain (PSTD/FD) Stokes absorption sign fix** — `_absorb_tau_from_power_law` in `run_jwave_sim.py` was missing a negative sign, making the Stokes (y=2) absorption correction energy-injecting instead of dissipative; this caused a persistent NaN on small, PML-dominated FOVs that survived several rounds of CFL/stability-margin tuning, since the instability was structural rather than a matter of insufficient headroom. Fixed; `auto_pad_for_pml`'s stencil-clearance floor and `jwave_wrapper.m`'s `jw_absorb_safety` margin (added while chasing this bug) are kept as legitimate, independent hardening. Both time-domain solvers now also track `max|p|` at every step (not just within the recording window) so a future instability's onset step is visible directly in the log
- **`pml_size: auto` sized from the fastest sound speed** — jwave's Helmholtz PML is fixed in voxels and does not scale with the local sound speed, so it was sized from `c_min` and under-absorbed where it bordered skull. It is now sized from `max(sound_speed)` (see [doc_jwave.md](doc_jwave.md#pml-thickness)); jwave runs with `pml_size: auto` get a thicker PML

#### Pseudo-CT acoustic property mapping
- With pseudo-CT, `medium_setup` caches the in-skull property distributions (pseudo-CT HU, density, sound speed, attenuation: summary statistics and histograms, plus the reference skull values) as `sub-XXX_<medium>_medium_stats<affix>.json` in `io.dir_cache`, for tools such as the Nexus; written on every run, not only in debug mode

Three new algorithms added for density, sound speed, and attenuation mapping (see [doc_pseudoCT.md](doc_pseudoCT.md)):

- `air-tissue` density — linear HU→ρ calibrated to air and cortical bone; matches `HUtoDensityAirTissue` in BabelBrain; required input for `pichardo` and `mcdannold` workflows
- `webb` sound speed — linear HU→c from Webb et al. (2018); scanner-specific slope and intercept configurable via `pct.webb_sos_slope` / `pct.webb_sos_intercept`
- `webb` attenuation — exponential HU model from Webb et al. (2020); scanner-specific coefficients configurable via `pct.webb_att_alpha0`, `.webb_att_beta`, `.webb_att_c`
- `pichardo` sound speed and attenuation — frequency-dependent 2D ρ–freq interpolation from the `MapPichardo.h5` look-up table in the BabelBrain submodule
- `mcdannold` sound speed and attenuation — polynomial ρ-based model (McDannold et al.)

## v0.5.0
*(2026-02-27)*

Major restructuring of the pipeline into discrete processing stages. Adds parallel multi-transducer support, an HTML simulation report, C++ backend, skull rubber-wrap, and heuristic transducer placement. Parameter names have changed and existing configs will need updating.

> ⚠️ **Migration note** — configs from v0.4.x will need updating:
> - `layer_labels` renamed to `layers`
> - Transducer and focus position fields renamed to `trans_pos` / `focus_pos` consistently
> - `grid_step_m` and `default_grid_size` removed
> - Grid expansion parameter renamed
> - Attenuation parameters renamed — consult `config_default.yaml`
> - Layer indexing field migrated from `layers` to `medium` throughout
> - Pipeline refactored into discrete processing stages — consult the documentation for current function entry points

#### Added

- [**feature**] C++ backend CPU & GPU support by @jkosciessa
- [**feature**] Parallel multi-transducer support for layered simulations by @dreamstimlab (see [PR #100](https://github.com/Donders-Institute/PRESTUS/pull/100))
- [**feature**] HTML simulation report — self-contained per-subject summary of acoustic and thermal outputs by @sirmrmarty
- [**feature**] Heuristic transducer placement — automated skull-surface search with configurable positioning criteria and ear exclusion (see [PR #109](https://github.com/Donders-Institute/PRESTUS/pull/109))
- [**skull**] Rubber-wrap skull mask inflation by @meijer-s (see [PR #103](https://github.com/Donders-Institute/PRESTUS/pull/103))
- [**thermal**] Flexible and standardised protocol timing specification aligned with TUSCalculator; protocol plot output
- [**thermal**] Additional thermal timeseries outputs (max per tissue, heating at focus)
- [**feature**] Per-step pipeline benchmarking: wall time, peak RAM, and disk usage logged at each stage
- [**grid**] Minimum PPW validation at source setup (`grid.min_ppw`, default 6); warns with the maximum `resolution_mm` that would satisfy the requirement
- [**calibration**] `calibration.opt_phase_precession` — optional constraint on element phases during amplitude/phase optimisation
- [**neuronav**] Updated Localite GUMMarkers parsing
- [**doc**] GitHub Pages [documentation](https://donders-institute.github.io/PRESTUS/) — parameters, functions, installation, quick start, and processing steps

#### Changed

- [**refactor**] Pipeline and core processing steps refactored; functions organised by processing stage
- [**axisymmetric**] Axisymmetric acoustic simulations now default to 3D thermal output

#### Fixed

- [**pCT**] kPlan skull density and sound speed regularised to water minimum
- [**acoustic**] GPU array correctly moved to CPU before NIfTI export
- [**calibration**] Unoptimized parameters no longer passed to Oneil recomputation
- [**savemat**] k-Wave source matrix saving can now be correctly deactivated; water simulations force-save matrix outputs

#### Deprecated/Removed

- [**feature**] Explicit `skull`-only simulation mode removed; equivalent behaviour is achieved by removing layers from the simulation setup
